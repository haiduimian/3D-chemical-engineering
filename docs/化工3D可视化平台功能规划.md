# 化工 3D 可视化平台 · 功能规划与技术路线

> 版本：v1.0 ｜ 日期：2026-09-01 ｜ 依托项目：`D:\自己的小应用\3D化工厂`（Vue3 + Three.js r180 + aurea-eden Diagram + Vite）
> 定位：从"演示级 3D 数字工厂"走向"面向真实化工生产场景的可视化平台"的系统性规划

---

## 1. 现状盘点：当前 3D 化工厂已具备 vs 真实平台缺口

| 维度 | 当前已具备（本项目） | 真实平台缺口 |
|---|---|---|
| 设备建模 | 8 类设备精细建模（罐/球罐/反应器/精馏塔/换热器/混合器/泵/搅拌罐），椭圆封头/护栏/爬梯/铭牌/指示灯 | 设备类型不全（缺加热炉/压缩机/离心机/干燥器/槽车等）；无 BIM/激光点云导入能力 |
| 管线系统 | 端口注册表驱动、L 形分层布线、圆角弯头、大小头、管托支撑、流向箭头 | 与 P&ID 数据脱节，无法从设计数据自动生成；无夹套/保温/伴热/盲端 |
| 动态仿真 | 流向脉冲、泵尾扇/搅拌旋转、阀门开度动画、数据柱 | 无物料平衡/能量平衡计算，无压力/流量沿程分布，无批次动态 |
| 数据联动 | MockDataSource（TAG_MAP 仪表值 + 报警 + 泵三态 + 阀开度） | 未对接真实 SCADA/DCS；无历史存储与回放；无预测性分析 |
| 安全监控 | 报警联动（设备灯红闪、仪表盘变红）、危险区域示意（围堰） | 无气体泄漏/火焰/超压超温的物理模拟，无疏散与事故演练 |
| 交互 | 视角旋转/聚焦、设备点击详情、管线联动高亮、仪表盘读数 | 无第一人称巡检、无 AR、无多人协作、无操作引导 |
| 培训考核 | — | 无开停车/应急处置模拟，无考核评分 |

> 结论：本项目已搭好"3D 场景引擎 + 程序化建模 + 数据驱动"的地基，缺口集中在 **数据接入、物理仿真、安全场景、协作培训** 四块。

## 3. 六大维度详细规划

### 3.1 工艺流程仿真 —— 优先级 **P0（必须）**

**落地痛点**：工艺人员无法直观看到物料从哪来、到哪去、参数如何沿程变化；开停车/联锁逻辑缺乏可视化校验；设计变更（P&ID 改管）与 3D 模型不同步。

**功能清单**

| 功能 | 说明 | 优先级 |
|---|---|---|
| 设备/管线程序化建模扩展 | 补加热炉、压缩机、离心机、槽车、火炬等类型；管线支持保温/伴热/夹套表现 | P0 |
| 物料流向全链路可视化 | 现有脉冲+箭头升级为"批次物料团"（颜色区分介质），支持沿程管径/流速变化 | P0 |
| 参数沿程可视化 | 管线按温度/压力着色（热力图），流量用管径/箭头大小映射 | P0 |
| 轻量物料平衡仿真 | 基于设备拓扑（端口注册表即拓扑）做稳态质量平衡计算，算出各段流量/压力估算值 | P1 |
| P&ID 数据导入 | 解析 P&ID/DXF 的设备位号、管线号、阀门清单，自动生成端口与管线路由 | P1 |
| 开停车顺序仿真 | 状态机驱动开/停车步序，联锁（interlock）逻辑可视化 | P1 |

**技术实现要点**（依托现有代码）
- 拓扑即端口：`src/layout/ports.ts` 已建立端口图 → 扩展为有向图（source/sink），流量用广度优先按质量平衡推算
- 管线热力图：管线独立材质（`BuiltPipe.tubeMat`）已支持按运行数据改 `emissive` 颜色 —— 直接按 tag 值映射色带即可
- 批次物料团：复用现有脉冲体系，把点脉冲改为"连续胶囊段"（TubeGeometry 短段沿曲线滑移）
- 开停车状态机：`processData.ts` 的 `DeviceStatus` 扩展为 `Phase`（开车/运行/停车/应急），驱动阀门/泵/灯联动

**验收标准**：① 全厂任意两点间可追溯物料路径与来源去向；② 管线颜色随参数实时变化（1s 刷新）；③ 开停车步序中设备/阀门按顺序动作，无逻辑冲突。

### 3.2 危险源与安全监控 —— 优先级 **P0（必须）**

**落地痛点**：事故不可演示（演练成本高、风险大）；GB 50493（可燃气体检测）、GB 30871（特殊作业）合规要求可燃/有毒气体报警与作业票联动；应急疏散依赖经验而非数据。

**功能清单**

| 功能 | 说明 | 优先级 |
|---|---|---|
| 气体泄漏扩散模拟 | 粒子系统（THREE.Points）+ 简化扩散模型（高斯烟羽/区域分级），风向/风速驱动 | P0 |
| 火焰/爆炸特效 | 火焰粒子 + PointLight 闪烁 + 后处理泛光（bloom）；爆炸冲击波半径圈 | P0 |
| 超压超温预警 | 设备压力/温度超限 → 设备整体泛红 + 警报声 + 页面弹窗（现有报警联动升级） | P0 |
| 危险区域划分 | 按物料特性（易燃/有毒/高压）渲染风险等级色块（半透明体），联动围堰/防火堤 | P0 |
| 事故演练模式 | 一键触发泄漏/着火/超温场景，按时间线播放，支持回放与复盘 | P1 |
| 应急疏散路径 | 场地图建模 + 路径规划（A*）+ 疏散箭头 + 集合点标记，与火灾联动 | P1 |
| 安全仪表联动 | 接入 SIS 联锁状态（SIL 等级），联锁触发时相关阀门/泵显示动作序列 | P1 |

**技术实现要点**
- 泄漏扩散：轻量实现用"粒子密度按浓度场分布"，不必引入 CFD——`THREE.Points` + Shader 控制粒子位置，浓度场用简化的高斯模型按风向扩散（每帧更新）；进阶可对接开源 CFD 结果（如 OpenFOAM 预计算的浓度场切片）
- 火焰：粒子 + 点光 + `EffectComposer` UnrealBloomPass（Three.js 官方示例）
- 风险分区：`CylinderGeometry`/`BoxGeometry` 半透明材质（`depthWrite:false` + 蓝/黄/红），风险等级来自 `HAZOP/LOPA` 静态表
- 疏散路径：地面网格化 + A* 搜索（可复用 `connectors/path.ts` 的 L 形思路做正交网格寻路），路径用贴地箭头带（扁 TubeGeometry）

**验收标准**：① 触发泄漏后粒子扩散方向随风向变化、浓度分级着色；② 超温设备在阈值点变红并伴随声光报警；③ 火灾演练中疏散路径实时重算并高亮最近集合点。

### 3.3 数据联动与数字孪生 —— 优先级 **P0（必须）**

**落地痛点**：DCS/SCADA 协议多样（OPC UA / Modbus TCP / 西门子 S7 / 霍尼韦尔 Experion），对接成本高；历史数据分散在各系统；报警与点位缺乏统一台账；预测性维护缺数据基础。

**功能清单**

| 功能 | 说明 | 优先级 |
|---|---|---|
| 实时数据接入网关 | OPC UA / Modbus TCP / MQTT 适配，点位表（tag→设备→3D 对象）统一注册 | P0 |
| 点位注册表标准化 | 现有 `TAG_MAP` 升级为可配置点位表（Excel/JSON 导入），含量程/单位/报警阈值/SIL 等级 | P0 |
| 设备状态数字孪生映射 | 实时值 → 3D 表现（转速/开度/颜色/灯），现有 `DeviceState` 机制扩展 | P0 |
| 历史数据存储 | 时序库（**TDengine**，与既有 cqcj-data-push 栈一致）存历史 + 实时双通道 | P0 |
| 历史回放 | 时间轴拖拽回放（设备/管线/数据柱按历史值驱动），支持多倍速 | P1 |
| 趋势分析 | 选中设备弹出趋势图（ECharts 对接 TDengine 查询），支持多 tag 对比 | P1 |
| 预测性维护 | 基于振动/温度/流量历史做异常检测（阈值 + 简单回归/机器学习），预测设备健康度 | P2 |
| 报表与看板 | 班报/日报自动生成（设备运行时长、报警统计、产量估算） | P2 |

**技术实现要点**
- 数据通道：实时走 MQTT（WebSocket）+ 历史查 TDengine（REST），与用户既有 cqcj-data-push 完全同栈
- 点位表：`src/data/processData.ts` 的 TAG_MAP 改为从 `public/points.json` 动态加载，格式与 DCS 组态表对齐
- 回放引擎：时间游标 → 批量取 TDengine 区间数据 → 每帧插值驱动 `updateBars/applyStates/updatePanels`
- 孪生一致性：所有 3D 表现**只能由点位数据驱动**（禁止硬编码），保证"一数一源"

**验收标准**：① 接入真实 OPC UA 模拟器（如 Prosys OPC UA Simulation Server）后画面 1s 内跟随；② 断点/报警数据在 TDengine 可查、可在 3D 中回放；③ 点位表增删改无需改代码。

### 3.4 巡检与操作交互 —— 优先级 **P1（重要）**

**落地痛点**：巡检路线靠纸面、执行靠自觉、到位率难考核；检修依赖老师傅经验，新人上手慢；异地专家会诊靠电话描述，效率低。

**功能清单**

| 功能 | 说明 | 优先级 |
|---|---|---|
| 虚拟巡检（第一人称） | PointerLockControls 漫游 + 步道行走，巡检点打卡（到达区域判定） | P0（该维度内） |
| 巡检路线编排 | 路线 = 点位序列（复用导览机位体系），支持定时任务与漏检提醒 | P0 |
| 设备定位检索 | 搜索位号 → 相机飞行 + 设备高亮 + 详情直达（现有 focusPipe 扩展） | P0 |
| 操作流程引导 | 步骤化操作指引（阀门开/关顺序、启泵前检查清单），每步对应 3D 高亮目标 | P1 |
| AR 辅助检修 | 手机/平板扫码（现场二维码 → 设备 3D 叠加 + 历史维修记录），基于 WebXR/8th Wall | P1 |
| 多人协作远程会诊 | WebRTC 音视频 + 场景状态同步（视角/标注/选取），专家远程标记 | P2 |

**技术实现要点**
- 第一人称：`PointerLockControls`（three/examples）+ 碰撞简化（以设备包围圆柱做地面/障碍判定）
- 巡检打卡：巡检点 = 位置 + 半径，进入半径内判定"到位"，记录时间戳上传
- 操作引导：流程 = JSON（步骤 → 目标设备/阀门 → 期望状态 → 校验规则），驱动高亮 + 状态机校验
- 协作同步：房间状态（设备状态/相机位姿/标注）用 WebSocket 广播，标注用 3D 画线（`Line2`）持久化
- AR：手机端复用既有 uni-app 经验（Image-acquisition 项目），二维码 → 位号 → REST 拉取模型/数据

**验收标准**：① 巡检任务发布后，按路线完成率可统计、漏检可追溯；② 操作引导步骤与 3D 高亮一一对应，错误操作被拦截并提示；③ 远程会诊时两端视角/标注实时一致（延迟 <500ms）。

### 3.5 培训与考核 —— 优先级 **P1（重要）**

**落地痛点**：新员工识流程/开停车培训周期长；真实事故演练成本高风险大；培训效果无量化。

**功能清单**

| 功能 | 说明 | 优先级 |
|---|---|---|
| 沉浸式安全培训 | 基于 3.2 的安全场景做"演示-讲解-体验"三阶课程（泄漏/火灾/超压） | P0（该维度内） |
| 开停车模拟操作 | 状态机驱动，学员操作阀门/泵，系统按顺序校验 | P0 |
| 应急处置模拟 | 事故触发 → 学员按 SOP 处置（关阀/启消防/报警/疏散），时间线评估 | P1 |
| 考核评分系统 | 规则引擎：操作顺序、时限、误操作扣分，生成成绩单 | P1 |
| 培训记录管理 | 学员档案、课程完成度、证书管理（对接既有 LIMS 用户体系） | P2 |

**技术实现要点**
- 操作对象：复用 `valves.setOpen()` / 泵状态接口，学员点击 3D 阀门/设备即"操作"
- 评分规则：状态机 + 规则表（如"未关进料阀就开停车 → 扣 20 分 + 报警音"），规则可配置化
- 事故时间线：预编排事件序列（0s 泄漏 → 30s 着火 → 60s 超压），与演练模式共用引擎
- 多端：Web 端操作，移动端可观看（视频流/WebRTC）

**验收标准**：① 学员完成开停车全流程 ≤ 规定时间且顺序无错；② 应急演练评分与人工评审结果相关性 ≥ 0.8；③ 培训记录可导出报表。

### 3.6 性能与兼容性 —— 优先级 **P0（基础保障）**

**落地痛点**：全厂设备数千台、管线上万段，浏览器崩溃/掉帧；工业现场电脑配置低（老 CPU、无独显）；Web 端部署要过内网和带宽限制。

**功能清单**

| 功能 | 说明 | 优先级 |
|---|---|---|
| 大场景渲染优化 | InstancedMesh（管线支撑/螺栓/护栏等重复件）、几何合并、LOD、区域剔除 | P0 |
| 轻量化部署 | 纹理压缩（KTX2/Basis）+ 模型 glTF 化 + gzip/brotli，首屏 < 5s | P0 |
| 低配兼容 | 自动降级（阴影关/粒子减半/分辨率缩放），兼容 Chrome/Edge 老版本 | P0 |
| 数据性能 | 万级 tag 订阅（数据分片 + WebWorker 解析），渲染层只消费变化值 | P0 |
| 内网部署 | 静态资源全本地化（无 CDN 依赖），支持 Docker 一键部署 | P1 |
| 工业硬件兼容 | 中控大屏（4K）、工控机触屏（多指缩放）、防爆平板（浏览器全屏） | P1 |
| 多场景切换 | 罐区/装置/全厂分级加载，模型按需异步加载（组件级 split） | P2 |

**技术实现要点**
- 几何合并：把静态重复件（护栏立柱/法兰螺栓/爬梯横档）合入 InstancedMesh，DrawCall 从 5000+ 降到 <300
- 材质分级：远景用简化材质（无 envMap/无阴影），近景全细节 —— `renderer.setViewport` + 多相机或简单的距离切换
- 数据层：MQTT 高频数据在 Worker 内聚合（1s 窗口），主线程只做 1Hz 更新（当前已是 1s 帧）
- 渲染预算：`renderer.shadowMap.enabled` 低配自动关；`pixelRatio` 上限 1.5
- 模型管线：程序化模型导出为 glTF（GLTFExporter）缓存，二次加载走 KTX2 压缩

**验收标准**：① 5000+ 设备 / 1 万段管线场景稳定 ≥50fps（中端配置）；② 弱 CPU（4 核无独显）下 ≥30fps 且可交互；③ 首屏加载 ≤5s（内网千兆），全资源本地无外网依赖。

## 4. 优先级总表（MoSCoW）

| 优先级 | 方向 | 核心价值 | 相对投入 |
|---|---|---|---|
| **P0-1** | 3.3 数据联动与孪生（实时接入 + 点位表 + TDengine） | 从"演示"变"平台"的分水岭 | 中（复用 MQTT/TDengine 栈） |
| **P0-2** | 3.1 工艺流程仿真（拓扑物料平衡 + 参数热力图） | 工艺人员日常价值 | 中（复用端口图） |
| **P0-3** | 3.2 危险源与安全监控（泄漏/火焰/超温 + 风险分区） | 安全合规刚需、演示冲击力最强 | 中高 |
| **P0-4** | 3.6 性能与兼容性 | 一切功能可用的前提 | 持续 |
| **P1** | 3.4 巡检与操作交互（第一人称 + 打卡 + 定位） | 运维提效、领导看板亮点 | 中 |
| **P1** | 3.5 培训与考核（开停车 + 应急演练 + 评分） | 安全培训刚需、落地快 | 中 |
| **P2** | 预测性维护 / AR 检修 / 多人会诊 / 多场景加载 | 锦上添花，视资源推进 | 高 |

**推荐落地顺序**：3.6 渲染预算打底 → 3.3 数据接入（打通 TDengine+MQTT）→ 3.1 物料平衡 → 3.2 安全场景 → 3.5 培训 → 3.4 巡检 → P2 项按需。

## 5. 分阶段路线图

| 阶段 | 内容 | 里程碑产物 | 周期参考 |
|---|---|---|---|
| M1 数据地基 | 点位表标准化、MQTT 网关、TDengine 接入、回放引擎 | 真实数据驱动画面 | 2-3 周 |

## 6. 关键技术选型汇总

| 领域 | 建议选型 | 理由（结合现有栈） |
|---|---|---|
| 3D 引擎 | Three.js r180（已用） | 生态成熟、示例全，教程与人才多 |
| 实时数据 | MQTT（MQTT.js） | 与 cqcj-data-push 同栈；DCS 网关侧用 Node-RED 做协议翻译 |
| 历史数据 | TDengine（REST/TAOS-RS） | 与既有 TDengine 经验一致；高吞吐、SQL 友好 |
| 工业协议 | OPC UA（Node-RED + node-red-contrib-opcua-server 测试） | 标准网关，模拟器可先行验证 |
| 状态管理 | Pinia（场景级 Store） | 与 Vue3 配套，跨组件共享点位表/实时值 |
| 图表 | ECharts 5 | 趋势/看板成熟方案 |
| AR | WebXR（渐进增强）+ 扫码位号 | 不依赖原生 App，Web 端优先 |
| 协作 | WebSocket 状态同步 + WebRTC 音视频 | 自研可控，无第三方服务依赖 |
| 部署 | Nginx 静态 + Docker Compose（含 TDengine） | 内网离线可部署 |

## 7. 落地风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| DCS 协议对接周期不可控 | M1 延期 | 先用 OPC UA 模拟器 + 既有 MQTT 数据源双通道，真实对接并行推进 |
| 3D 模型需求膨胀（领导要求"像真厂"） | 范围失控 | 坚持程序化建模 + 端口化管线（可参数化），明确"数据真实优先于几何真实" |
| 安全场景被质疑不专业（非 CFD） | 演示可信度 | 明确标注"教学演示级扩散/火焰模拟"，与正式 CFD/HAZOP 结论并列展示 |
| 万级 tag 浏览器卡顿 | 性能不达标 | 数据分片 + Worker 聚合 + 1Hz 渲染预算（3.6 的 P0 项先行） |
| 多系统权限/账号体系冲突 | 落地阻力 | 单点登录对接既有 LIMS/MES 用户体系，3D 平台不自建账号 |
