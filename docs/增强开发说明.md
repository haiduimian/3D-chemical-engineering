## 1. 现状诊断

### 1.1 管线未连接根因

当前 `src/layout/plantLayout.ts` 中 13 条管线的 `waypoints` **全部为硬编码坐标**，与设备模型内部的管口位置没有契约关系：

- 设备重构（精细化建模）后管口位置已明确（如 R-101 进料口在 `(-22.2, 4.9, 18)`），但管线终点仍停留在旧坐标，导致**管线在设备外 1~7m 处悬空结束**；
- 管线与设备之间没有任何"接口吸附"逻辑，也没有统一的高度层约定（地面层 y≈1、管廊层 y=6、高位层 y=17 等）；
- 部分管线只是"路过"泵位（如酸循环线经过 P-104 所在位置但未串接泵）。

## 2. 总体架构变更

```
plantLayout.ts          plantShapes.ts            pipes.ts
┌──────────────┐  ports  ┌──────────────┐        ┌──────────────────┐
│ 设备定义       ├───────▶│ 构建时输出      │        │ 管线生成器         │
│ EQUIPMENTS    │        │ userData.ports│        │ port→port 自动路径 │
│ PIPES(引用端口)│        └──────────────┘        │ + 流向箭头 + 阀件  │
└──────────────┘                                  └──────────────────┘
        │
processData.ts（扩展）──▶ MockDataSource 输出：仪表值 / 泵状态 / 阀开度
```

**核心原则：设备管口是唯一事实来源（Single Source of Truth）。**
管线不再写死坐标，而是声明 `ports: [出口端口ID, 入口端口ID]` + 中间"途径点"（如管廊高度、泵位），构建时由 `resolvePipePath()` 将端口引用展开为绝对坐标。

## 3. 模块一：管线连接修复

### 3.1 实现目标

1. 全部 13 条管线端点**精确吸附**到设备管口，无悬空、无穿模；
2. 管线路径遵循厂区高度层约定（地面 y≈1 / 管廊 y=6 / 高位 y=17+），横平竖直、带圆角弯头；
3. 泵类设备**串接在管线中**（进泵→泵→出泵），管廊过路管线不穿设备。

### 3.2 技术方案

**(a) 设备接口注册表（新增 `src/layout/ports.ts`）**

```ts
export interface PortDef {
  id: string            // 全局唯一，如 'V101-OUT-1'
  elementId: string     // 所属设备
  /** 相对设备原点(x,z)的偏移 */
  offset: [number, number, number]   // [dx, dy, dz]
  /** 管口朝向（出料方向） */
  dir: [number, number, number]
  diameter: number      // 口径
  kind: 'nozzle' | 'flange' | 'tankTop' | 'tankBottom'
}

// 端口清单（坐标 = 设备坐标 + offset，与 plantShapes 管口建模位置一致）
export const PORTS: Record<string, PortDef> = {
  'V101-OUT-1': { elementId: 'V-101', offset: [-2, 0.85, 4],  dir: [-1, 0, 1], diameter: 0.35, kind: 'nozzle' },
  'V101-IN-1':  { elementId: 'V-101', offset: [4, 1.15, -1.6], dir: [1, 0, 0],  diameter: 0.35, kind: 'nozzle' },
  // …其余端口参照 plantShapes.ts 中各设备管口建模坐标逐一登记
}
```

**(b) 管线定义改为端口引用（改 `plantLayout.ts` 的 `PipeDef`）**

```ts
export interface PipeDef {
  id: string
  color: keyof typeof PIPE_COLORS
  diameter: number
  flow: number               // >0 正向；<0 反向（流向箭头/脉冲方向依据）
  from: string               // 端口 ID（PIPES 起点）
  to: string                 // 端口 ID（PIPES 终点）
  /** 中间途径点（可空）：仅声明 管廊高度 / 泵位 / 转折点 */
  via?: { x: number; y?: number; z: number }[]
}
```

**(c) 路径解析器（新增 `src/connectors/path.ts`）**

```ts
export function resolvePipePath(def: PipeDef): THREE.Vector3[] {
  // 1. 由 from/to 端口 → 设备绝对坐标（EQUIPMENTS.find(x) + offset）
  // 2. 路径骨架：水平出管口 → 垂直爬升到 via 高度 → 水平走管廊 → 垂直下降 → 水平入管口
  // 3. 出/入段首末点按端口 dir 外延 0.4m（避免贴脸穿模）
  // 4. 圆角化（复用现有 CatmullRom tension=0.05 近似折线）
}
```

### 3.3 验收标准

| # | 验收项 | 验证方式 |
|---|---|---|
| A1 | 13 条管线**零悬空**：放大任一管线端点，均贴合设备管口 | 拖拽视角逐条检查端点 |
| A2 | 管线不过设备实体（穿过罐体/塔体内部） | 旋转视角 360° 观察 |
| A3 | 泵管线真实串接 P-101~105：入口法兰→泵体→出口法兰 | 泵区视角检查 |
| A4 | 管廊段管线高度与管廊横梁一致（y=6 / y=8），不穿梁 | 管廊视角检查 |
| A5 | 修改任一设备坐标/尺寸后，其管线**自动跟随**（无手动改坐标） | 改 `EQUIPMENTS.x` 验证自动重排 |

## 4. 模块二：3D 交互增强（视角旋转 + 物料流向）

### 4.1 视角旋转

- **现状**：已支持左键旋转 / 右键平移 / 滚轮缩放（上次已修复 ANALYZE 后视角锁死 bug）。
- **增强目标**：
  1. 双击设备 → 相机平滑飞行至设备近景（复用 `flyTo` 补间）；
  2. 增加**焦点锁定**：按 `F` 键将 `controls.target` 锁定到选中设备中心，旋转始终围绕设备；
  3. 键盘方向键平移视角；
  4. 保证 ANALYZE/VIEW 切换后旋转控制不丢失（回归用例）。

### 4.2 物料流向展示

- **现状**：发光"脉冲小球"沿管线曲线移动（`animatePipes`），但无方向箭头，脉冲方向与管线真实走向无视觉对应。
- **增强目标**：
  1. **流向箭头**：沿每根管线每隔 ~4m 放置一个锥形箭头（`ConeGeometry`，朝向 `curve.getTangentAt(u)`），材质用管线色 + 发光；管线较长时箭头数量随长度自动增加；
  2. **脉冲方向语义化**：脉冲 `u` 递增方向 = `flow > 0` 正向，`flow < 0` 反向推进；脉冲改为"彗星拖尾"（前亮后暗），强化方向感；
  3. **联动高亮**：点击设备后，与该设备相连的全部管线高亮（材质 `emissiveIntensity` 提升 + 箭头放大），无关管线半透明降噪；
  4. **速度可视化**：管线宽度/发光强度随 `flow` 值线性变化（大流量更亮更粗）；
  5. 图层开关：UI 增加"流向箭头 / 脉冲 / 管线发光"三个开关。

### 4.3 验收标准

| # | 验收项 | 验证方式 |
|---|---|---|
| B1 | 所有管线可见**指向清晰的方向箭头**，且方向与物料工艺走向一致（罐区→反应区→塔区→球罐） | 总览视角观察流向链条 |
| B2 | 脉冲沿箭头方向移动（无逆向） | 停留观察 5s |
| B3 | 点击 V-101 → 其连接管线高亮，其余管线变淡 | 点击设备验证 |
| B4 | 双击设备 → 相机平滑聚焦；`F` 键锁定旋转中心 | 操作验证 |
| B5 | 切到 ANALYZE 再切回 VIEW，旋转/缩放全部恢复 | 回归验证 |

## 5. 模块三：设备运行状态显示

### 5.1 数据源扩展（`processData.ts`）

```ts
export type DeviceStatus = 'RUN' | 'STOP' | 'FAULT'

export interface DeviceState {
  status: DeviceStatus      // 泵/搅拌器运行态
  valveOpen: number         // 0~100 阀门开度（与管线上的阀件关联）
}

// Mock 每 1s 一帧输出：仪表值 + 报警 + 设备状态
export class MockDataSource {
  onTick(cb: (points, alarms, deviceStates: Record<string, DeviceState>) => void)
}
```

### 5.2 阀门建模与状态显示

- **阀件模型**（新增 `src/shapes/valves.ts`）：小型闸阀（阀体 + 手轮 + 支架），按管线节点自动放置：
  - 每条管线 `from/to` 端口附近、管廊支线分叉处、泵出入口各放一个；
  - 阀门开度状态：**手轮旋转角度 = 开度 × 270°**（模拟开/关），阀杆伸缩量 = 开度；
  - 阀体指示灯：开度 ≥ 95% 绿色（全开）、5%~95% 黄色（节流）、<5% 红色（关闭）；
  - 阀门状态与 `deviceStates.valveOpen` 联动，1s 刷新。

### 5.3 泵/搅拌器状态显示

| 状态 | 电机指示灯 | 尾扇动画 | 泵体表现 |
|---|---|---|---|
| RUN | 绿色常亮 | 旋转（`fan.rotation.x += 0.3`） | 泵体轻微 `emissive` 脉冲 |
| STOP | 灰色熄灭 | 停转 | 无 |
| FAULT | 红色闪烁（0.5s 周期） | 停转 | 泵体泛红 + 报警标签 |

- 实现：`PlantScene.updateDeviceStates(states)` 遍历 `equipmentGroups`，按 `userData.elementId` 匹配；
- 报警联动：`alarms` 含某设备 tag 时，该设备指示灯强制变红闪烁（优先于运行色）。

### 5.4 验收标准

| # | 验收项 | 验证方式 |
|---|---|---|
| C1 | 每根管线/泵前后出现阀件，手轮角度随开度变化 | 观察阀门区 |
| C2 | 阀门指示灯颜色正确（开度→绿/黄/红） | Mock 中改变开度验证 |
| C3 | 泵尾扇随 RUN/STOP/FAULT 切换（转/停/停+红闪） | 观察泵区 |
| C4 | 报警设备指示灯红色闪烁，解除后恢复 | 制造报警（提高 noise 或 alarmHigh） |
| C5 | 状态数据 1s 刷新，无卡顿 | 观察 10s |

### 6.1 管道连接（见模块一，端口吸附即管道连接修复）

### 6.2 仪表读数（设备端数字仪表盘）

- **现状**：仪表值仅以"数据柱 + 屏幕角落信息卡"呈现，设备本体上看不到读数。
- **增强目标**：设备侧壁/塔身粘贴 **CanvasTexture 数字仪表盘**：
  - 面板内容：tag 名（如 `TI-R101`）+ 实时数值 + 单位 + 正常/报警底色；
  - 每个设备挂 1~2 块（挂载位置用端口注册表同源坐标）；
  - 每帧 `texture.needsUpdate = true` 随 Mock 数据刷新；
  - 报警时面板变红边框 + 数值闪烁。
- 注：与现有"数据柱"（ANALYZE 模式）并存——数据柱用于远观趋势，仪表盘用于近观读数。

### 6.3 设备结构细节

- 已完成一轮精细化（椭圆封头/护栏/爬梯/平台/焊缝/铭牌/指示灯/液位计/管口）；
- 本阶段补充：
  1. 设备**进出料管口加装真实法兰接口**，与管线端头法兰配对（直径对齐）；
  2. 塔类增加**塔顶吊柱 + 塔盘人孔**序列（可视化塔盘间距）；
  3. 换热器壳体增加**保温中段**（两端裸露 + 中段铝皮横纹，体现真实保温施工）；
  4. 球罐增加**赤道平台护栏与盘梯**完整闭合。

### 6.4 设备详情弹层（交互增强）

- 点击设备 → 右侧信息卡升级为**详情面板**：
  - 静态：位号 / 名称 / 类型 / 材质 / 操作条件；
  - 动态：实时仪表值（与 TAG_MAP 联动）+ 运行状态徽标 + 报警列表；
  - 联动：面板内列出该设备**所有连接管线**（名称 + 流向 + 流量），点击管线 → 视角飞行至该管线并高亮。
