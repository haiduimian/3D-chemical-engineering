# AI 迭代操作手册（Standard Operating Manual）

> 适用：3D 化工数字工厂（Vue3 + three.js 0.180 + aurea-eden + Vite）
> 目标：任何 AI（或工程师）只读本手册即可独立执行完整的迭代闭环：
> **读白皮书 → 定目标 → 调研 → 实现 → 验收 → 报告与方案 → 提交部署 → 归档**
> 版本：v1（对应 R10 实战沉淀）

## 0. 心智模型：五阶段闭环


## 2. 三条总纪律（违反必出事故，已反复验证）

1. **源码文件一律用文件工具（write/edit）读写；pwsh 只做构建/运行/清理。**
   pwsh 的 `Get-Content/Set-Content` 按本地 ANSI 编码读写 UTF-8 源码会把中文注释整段写坏（R10 事故）。
   若已损坏：`git checkout -- <file>` 恢复上一提交版本。
2. **headless 验收一律走 `vite preview`（端口 4173），禁止走 `vite dev`（5180）。**
   dev 的 HMR 会在源码热更时全量重载无头页面 → 出现"时间线错位/状态残影"伪异常（R9 事故）。
3. **验收前先清理僵尸 headless Edge 进程。** 残留 msedge（数百秒 CPU）会把 SwiftShader 渲染拖慢 3~5 倍。
   清理命令见 05 部署文档第 4 节。

## 3. 速度与预算现实（SwiftShader 软件渲染）

- 每次全量 `timeod-check` ≈ 25~35 min；`capture-frames` ≈ 5~10 min；`sky-*-probe` ≈ 3~5 min。
- **调参回路用快速探针（5 min 级），认证才跑全量。** 先探针收敛 → 最后全量认证一次。
- 全天预算建议：实现 2~4h，验证 1~2h，文档 0.5~1h。

## 4. 未知文件甄别（新会话必做）

进入工作区后先 `git status --short`：
- 识别工作树中**不属于当前会话**的未跟踪文件（如历史遗留 `scripts/_*.mjs`、`dist-bak-*` 备份、
  `docs/research/*-raw.json` 调研原文）。规则：**生成物/中间产物不进版本库**（.gitignore 兜底），
  内容不明的先保留工作树、在回复中向用户报告归属，不擅自提交或删除。
- `.gitignore` 应始终包含：`node_modules / dist / dist-bak-* / .shots / .deploy-gh-pages / *.log`
