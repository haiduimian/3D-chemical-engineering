# 05 部署与发布（git 推送 + gh-pages + 线上验证 + token 安全）

## 0. 前置

- 仓库：`https://github.com/haiduimian/3D-chemical-engineering`（origin 已配置）
- 分支语义：`main` = 源码；`gh-pages` = 站点产物（index.html + assets + points.json，base=/3D-chemical-engineering/）
- 部署前置：`npm run build` 必须刚跑过（本迭代最终 dist）。

## 1. 提交（先审查后提交）

```powershell
git add -A
git status --short        # ★ 逐行审查：只应有本轮确认文件
# 发现杂项（dist-bak-*、_tmp/*、陌生脚本……）：
#   git reset -q                           → 取消暂存
#   .gitignore 增加模式（如 dist-bak-*）
#   git add <本轮文件清单>                   → 只加确认文件
git commit -m "feat(3d): R<N> <一句话主题>"
```
注意：`git add -A` 会把任何未跟踪文件一并带上——**先 status 后 commit**，未知文件
保留在工作树、向用户报告（见 00-README §4）。

## 2. 推送（token 注入方式，不写进 remote 配置）

```powershell
git push "https://x-access-token:<TOKEN>@github.com/haiduimian/3D-chemical-engineering.git" main
```
预期输出：`<old>..<new>  main -> main`。
PowerShell 会把 git 的进度提示当作 stderr（红色）——**只要出现 `main -> main` 即成功**。

## 3. gh-pages 部署（worktree 方式）

```powershell
# 1) 挂出 gh-pages 分支到 .deploy-gh-pages（已在 .gitignore）
git worktree add -f .deploy-gh-pages gh-pages

# 2) 同步 dist（覆盖 + 删除旧哈希资源）
Copy-Item -Path 'dist\*' -Destination '.deploy-gh-pages\' -Recurse -Force
Get-ChildItem '.deploy-gh-pages\assets' -File |
  Where-Object { -not (Test-Path "dist\assets\$($_.Name)") } |
  ForEach-Object { Remove-Item $_.FullName -Force }

# 3) 提交推送
git -C .deploy-gh-pages add -A
git -C .deploy-gh-pages commit -m "deploy: R<N> <一句话>"
git -C .deploy-gh-pages push "https://x-access-token:<TOKEN>@github.com/haiduimian/3D-chemical-engineering.git" gh-pages

# 4) 清理
git worktree remove .deploy-gh-pages --force
git worktree prune
```

## 4. 线上验证（部署后必做）

```powershell
Start-Sleep -Seconds 40   # GitHub Pages 生效延迟
$r = Invoke-WebRequest -Uri 'https://haiduimian.github.io/3D-chemical-engineering/' -UseBasicParsing -TimeoutSec 30
$r.StatusCode                             # 期望 200
$r.Content -match '<新JS哈希>'             # 期望 True（新构建的 index-*.js）
(Invoke-WebRequest -Uri '.../assets/<新JS哈希>' -Method Head -TimeoutSec 30).StatusCode   # 200
```
任一失败：等 60s 重试 → 仍失败则检查 gh-pages 分支内容/worktree 是否干净。

## 5. Token 安全（硬性）

- **token 只出现在一次性 push URL 中**；绝不写入 `.git/config`、脚本、文档、仓库。
- 每次使用后提醒用户**轮换**（GitHub → Settings → Developer settings → Personal access tokens）。
- 白皮书 §3 部署痛点同步记录"使用过的 token 已轮换"。
- 长期方案：N 队列已排 `CI workflow`（gh-pages Actions），届时 token 入 Secrets，不再进命令行。

## 6. 回滚

- 源码回滚：`git revert <bad-commit>` 或 `git reset --hard <good>` 后按 §2 推送 main。
- 站点回滚：worktree 检出目标 gh-pages 提交 → 重新 push gh-pages（同 §3 流程，dist 换旧档）。

## 7. 部署后收尾清单

- [ ] main 与 gh-pages 均已推送（记录提交哈希）
- [ ] 线上 HTTP 200 且引用新 JS 哈希
- [ ] token 轮换提醒已传达；如需轮换已完成
- [ ] 重申下轮入口：白皮书 R<N> 已是最新版
